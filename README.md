# NutriPlan

Healthy halal meal planner, calorie tracker and progress charts. 60 protein-forward
recipes built on ingredients you can buy locally. All data stays on the device —
no account, no server, nothing uploaded.

This repo builds **two** things from the same source in `www/`:

| | What your family gets | What you have to install |
|---|---|---|
| **APK** | A `.apk` file to sideload | Nothing (GitHub builds it) or Android Studio |
| **PWA** | A link they tap "Install" on | Nothing |

---

## Path A — Get an APK without installing anything

GitHub compiles it for you on their machines.

1. Create a new repo on GitHub and push this folder to it.
2. Open the **Actions** tab. The `Build Android APK` workflow starts on its own
   (or press **Run workflow**).
3. Wait ~4 minutes. Open the finished run, scroll to **Artifacts**, download
   **NutriPlan-APK**.
4. Unzip it. Inside is `NutriPlan.apk` — that's the file you send people.

Nothing to install locally. This is the fastest route.

## Path B — Build the APK on your own machine

Needs **JDK 17** and the Android SDK (Android Studio bundles both).
JDK 21 will fail — Android Gradle Plugin 8.2 expects 17.

```bash
npm install
npm run apk
```

The APK lands at:

```
android/app/build/outputs/apk/debug/app-debug.apk
```

`npm run open` opens the project in Android Studio if you prefer buttons.

## Sending it to family and friends

Android blocks apps that didn't come from the Play Store, so tell them:

1. Download the `.apk` (WhatsApp compresses unknown files — use Google Drive,
   Telegram, or email instead).
2. Tap it. Android says *"For your security, your phone can't install unknown apps
   from this source"*.
3. Tap **Settings** on that prompt → enable **Allow from this source** → go back
   → **Install**.
4. Google Play Protect may add *"Unsafe app blocked"* → **More details** →
   **Install anyway**. This is normal for any app not on the Play Store.

**That's four confusing steps for a non-technical relative.** If they just want to
use the app, the link below is genuinely easier for them.

### The easier alternative: send a link

1. Drag the `www` folder onto <https://app.netlify.com/drop>. You get a URL instantly, free.
2. Send that URL.
3. They open it in Chrome → menu **⋮** → **Install app** (or **Add to Home screen**).

They get the same icon, the same fullscreen app, and it works offline. No security
warnings, no settings to change. Updates are instant — you re-drag the folder and
everyone has the new version without reinstalling anything.

## Where the data lives

`localStorage`, on the device. It survives closing the app, rebooting the phone and
losing signal. It is destroyed by: uninstalling the app, clearing its storage in
Android settings, or using a private browser window.

**There is no cloud backup.** The app has *Download backup file* and *Restore from
backup* in **Me → Your data**, and nags for a backup every two weeks once there's
data worth keeping. Tell whoever you send it to.

APK and PWA keep **separate** storage. Data does not move between them — export
from one and import into the other.

## Publishing to the Play Store later

Three changes needed when you get there:

1. **Target SDK 35.** Google requires it for new submissions. In
   `android/variables.gradle` set `compileSdkVersion` and `targetSdkVersion` to `35`,
   and in `android/build.gradle` bump the AGP classpath to `8.6.0` or newer.
   Left at 34 here because that is the version this project was generated and
   checked against.
2. **A signing key.** Every Play Store app needs one, and *you can never change it* —
   losing it means you can't update your own app. Generate and back it up:

   ```bash
   keytool -genkey -v -keystore nutriplan.jks -keyalg RSA \
           -keysize 2048 -validity 10000 -alias nutriplan
   ```

   Then create `android/keystore.properties`:

   ```properties
   storeFile=../nutriplan.jks
   storePassword=yourpassword
   keyAlias=nutriplan
   keyPassword=yourpassword
   ```

   `npm run apk:release` now produces a signed release build. This file is
   gitignored — keep the `.jks` somewhere safe and off GitHub.
3. **A Play Console account** — US$25, one time.

## Project layout

```
www/                      the entire app — one HTML file plus icons
  index.html              markup, styles, logic, recipe data
  manifest.json           PWA metadata
  sw.js                   offline service worker
android/                  native shell (generated by Capacitor)
.github/workflows/        cloud APK build
capacitor.config.json     app id, name, splash settings
```

To change the app: **edit `www/index.html`**, then `npm run sync`. Everything
else is scaffolding.

`com.altamash.nutriplan` is the package id. It must be unique on the Play Store
and can't be changed after publishing — change it now if you want something else,
in `capacitor.config.json` and `android/app/build.gradle`.

## Checking the app's own tests

Open the app, then in the browser console run `__test()`. It verifies the BMR
formulas against published reference values, the ft/in conversions, that every
recipe's calories match its macros, and that generated meal plans land within
250 kcal of target.
